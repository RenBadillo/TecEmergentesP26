UR3 Digital Twin
Unity XR

Sistema completo de gemelo digital del brazo robótico Universal Robots UR3, con cinemática inversa física, pipeline de seguridad multicapa, hand tracking en Meta Quest y comunicación bidireccional con el robot real mediante Flask.

4 Capas de sistema

6 Endpoints Flask

¿Qué hace este sistema?

Conecta la realidad mixta con un brazo robótico industrial real. El usuario interactúa en 3D, el sistema valida el movimiento digitalmente y solo entonces lo envía al hardware físico.

Entrada

Interacción Natural

Gesto pinch con los dedos, drag de objetos XR o teclado flotante MRTK para definir poses objetivo en el espacio 3D.

Procesamiento

IK + Seguridad

CCD iterativo con límites articulares, verificación de singularidades, continuidad y detección de autocolisiones por física.

Salida

Robot Real

Trayectoria validada enviada paso a paso al servidor Flask → URScript → UR3 físico. Retroalimentación en tiempo real vía HTTP.

ℹ
El sistema utiliza un robot ghost (gemelo invisible) para simular y validar toda la trayectoria antes de mover el robot real. Si cualquier check falla, el movimiento se cancela con un mensaje descriptivo.

Tecnologías principales

Motor

Unity 2022.3 LTS

Motor de juego con soporte completo para física, XR, render, UI y compilación Android para Meta Quest.

Headset

Meta Quest 3

Dispositivo MR con hand tracking nativo, passthrough color y 6DoF posicional. SDK v83 usado en este proyecto.

Backend

Flask + ur_rtde

Servidor Python liviano que recibe comandos de Unity y los traduce a URScript para el controlador del UR3.

Robot

Universal Robots UR3

Brazo colaborativo de 6 DOF, carga útil 3 kg, alcance 500 mm. Controlado por URScript sobre red TCP/IP.

El sistema se organiza en capas con responsabilidades bien definidas, desde la interfaz del usuario hasta el hardware industrial.

Capa 1 — Interacción MR Interface
Hardware Meta Quest · Hand tracking · UI 3D

Capa de entrada del usuario. Captura gestos físicos (pinch con hand tracking OVR), posiciones espaciales y selección de menús flotantes. Construye la estructura de comando con tipo de movimiento y coordenadas objetivo. También permite dibujar trayectorias 3D directamente en el aire.

IK · Interpolación · Restricciones cinemáticas

Núcleo matemático del sistema. Calcula la cinemática inversa, interpola la trayectoria (MoveJ / MoveL / MoveC) y aplica todas las restricciones de seguridad sobre el robot ghost: límites articulares, autocolisiones, colisión con superficies y workspace. Ejecución física del movimiento. El controlador del UR3 recibe comandos URScript del servidor Flask, ejecuta el movimiento articular y retorna su pose actual como retroalimentación a la Capa 3. La cámara en el efector final puede enviar frames a Unity para visualización en tiempo real.

Flujo de Ejecución Completo

Desde el gesto del usuario hasta el movimiento físico del robot, pasando por cada capa y validación.

1
Usuario define el objetivo CAPA 1
El usuario arrastra el DragTarget (esfera XR) o usa el gesto de pinch con DrawTrajectoryMeta para dibujar una trayectoria desde el efector final (Link6).
2
UR3WorkspaceLimiter restringe en tiempo real SEGURIDAD
En cada LateUpdate, el limiter proyecta la posición del DragTarget al punto válido más cercano dentro del workspace operativo del UR3 (caja AABB + anillo radial XZ), antes de que el usuario suelte.
// Restricción activa mientras el usuario mueve el target
Vector3 p = workspaceFrame.InverseTransformPoint(worldPoint);
p.y = Mathf.Clamp(p.y, minY, maxY);               // altura
float r = new Vector2(p.x, p.z).magnitude;
r = Mathf.Clamp(r, minRadiusXZ, maxRadiusXZ);     // radio XZ
3
Pose copiada → ExecutionTarget CAPA 1
Al soltar el DragTarget, RoutinePlacementController.OnTargetUnselected() copia la posición al ExecutionTarget y muestra el Canvas con el botón "Iniciar Rutina" orientado hacia la cámara principal.
4
UR3MotionValidator — validación completa CAPA 2
El validador inicializa el GhostRobot con el estado actual del LiveRobot y simula la trayectoria interpolando N muestras. Para cada muestra ejecuta los 5 checks en orden:
Para cada muestra s = 1…samplesPerSegment:
  pos = Lerp(startPos, targetPos, s/N)
  
  ① PreviewSolveToPosition(pos)      → IK converge?
  ② CheckJointMargins(qNow)          → ≥ 10° del límite?
  ③ CheckSingularityHeuristic(qNow)  → |q3|>7° y |q5|>5°?
  ④ CheckContinuity(qPrev, qNow)     → Δq < 40°/paso?
  ⑤ HasSelfCollision()               → sin penetración?
  
  Si cualquier check falla → return false + reason
5
UR3FlaskSender genera y envía pasos CAPA 3
Con la trayectoria aprobada, el sender vuelve a simularla sobre el GhostRobot y construye el payload de cada paso, convirtiendo los ángulos de grados a radianes para el servidor Flask.
// Cada paso enviado vía POST
{
  "id_figura":    "figura_001",
  "id_movimiento": "figura_001",
  "paso":         3,         // 1…samplesPerSegment
  "j1"…"j6":      0.523      // en RADIANES
}
6
Robot UR3 ejecuta el movimiento CAPA 4
El servidor Flask traduce cada payload a URScript y lo envía al controlador del UR3. El robot ejecuta el movimiento articular. En paralelo, UR3Client hace polling cada 100 ms al endpoint /joints para actualizar el gemelo con la pose real.
7
Retroalimentación visual CAPA 3
CameraVideoButton solicita frames al endpoint /snapshot.jpg a los FPS configurados y los proyecta en el plano 3D de la escena. UR3JointDebugger imprime los ángulos del gemelo en el TextMeshPro de la UI XR.

Núcleo — Cinemática Inversa

Los scripts que resuelven cómo debe moverse el robot para alcanzar un punto en el espacio.

UR3SimpleIKPhysical
UR3SimpleIKPhysical.cs — Componente central
CORE +

Script más importante del proyecto. Implementa un solucionador IK iterativo tipo CCD proyectado sobre ejes locales con dinámica física simulada: velocidades, aceleraciones y límites articulares por joint. Puede operar en dos modos: Live (movimiento en tiempo real en LateUpdate) o Ghost (resolución offline con PreviewSolveToPosition).

⚠
Diferencia clave Live vs Ghost: LateUpdate aplica dinámica (velocidad, aceleración, step budgets por frame). PreviewSolveToPosition resuelve el IK puro sin límites de velocidad, en N iteraciones, para validación y envío.

Pipeline de Seguridad

Cuatro scripts trabajan en conjunto para garantizar que ningún movimiento peligroso llegue al robot real. Todo se valida sobre el robot ghost antes de ejecutar.

✓
Si todos los checks pasan → UR3FlaskSender puede enviar la trayectoria. Si cualquiera falla → se retorna false con un string reason descriptivo y el movimiento se cancela.
UR3KinematicSafetyChecker
UR3KinematicSafetyChecker.cs — 3 checks cinemáticos
SAFETY +

Verifica condiciones cinemáticas sobre vectores de ángulos. Los tres métodos públicos retornan bool y un out string reason con la descripción exacta del problema.

①
CheckJointMargins — Límites articulares
Verifica que ningún joint esté dentro del margen de seguridad de sus límites mecánicos (default: 10° antes del tope). Previene bloqueos y daño mecánico.
// Fórmula de verificación
q[i] > qMin[i] + margin && q[i] < qMax[i] - margin
②
CheckSingularityHeuristic — Singularidades
Detecta configuraciones donde la muñeca (q5 ≈ 0°) o el codo (q3 ≈ 0°) entran en singularidad, causando movimientos erráticos e impredecibles.
|q5| < wristSingularityDeg  (default 5°) → reject
|q3| < elbowSingularityDeg  (default 7°) → reject
③
CheckContinuity — Continuidad de trayectoria
Comprueba que el salto entre el paso anterior y el actual no sea brusco. Usa Mathf.DeltaAngle para manejar correctamente los cruces del ±180°.
Δq = Mathf.DeltaAngle(qPrev[i], qNow[i])
if |Δq| > maxJointJumpDeg (40°) → reject
ParámetroDefaultPropósito
qMinDeg / qMaxDeg±180°Límites articulares de cada joint
jointMarginDeg10°Margen de seguridad antes del límite
wristSingularityDeg5°Umbral de singularidad de muñeca (q5)
elbowSingularityDeg7°Umbral de singularidad de codo (q3)
maxJointJumpDeg40°Salto máximo permitido entre pasos
UR3SelfCollisionChecker
UR3SelfCollisionChecker.cs — Colisiones por física
SAFETY +

Detecta autocolisiones del robot usando Physics.ComputePenetration entre todos los colliders de los links. Compara cada par no adyacente (los adyacentes siempre se tocan y son ignorados por defecto).

// Núcleo del checker
Physics.SyncTransforms();

for i in links:
  for j in links (j > i):
    if ignoreAdjacentLinks && |i-j| == 1: continue
    
    overlap = Physics.ComputePenetration(
      links[i].collider, pos_i, rot_i,
      links[j].collider, pos_j, rot_j,
      out direction, out distance
    )
    
    if overlap → return true, "Autocolisión: {links[i].name} ↔ {links[j].name}"
ℹ
Requiere que cada link tenga un Collider configurado y que la capa de física no ignore colisiones entre los layers del robot. El LinkColliderEntry[] se configura en el Inspector.

Interacción XR

Scripts que conectan los gestos del usuario en Meta Quest con el sistema de control del robot.

DrawTrajectoryMeta
DrawTrajectoryMeta.cs — Hand tracking OVR
+

Permite dibujar trayectorias en el aire usando el gesto pinch (índice + pulgar). El trazo siempre inicia desde Link6 (efector final) para garantizar continuidad con el estado del robot. Los puntos se guardan en coordenadas locales del trajectoryRoot y pueden exportarse como CSV.

Ciclo de vida del trazo

// 1. Inicio de pinch → primer punto = Link6
startLocal = trajectoryRoot.InverseTransformPoint(link6.position);

// 2. Durante pinch → captura si distancia ≥ minDistanceBetweenPoints
if dist >= minDistanceBetweenPoints (1cm): AddPoint(fingerLocal)

// 3. Fin de pinch → export
if printCoordinatesWhenFinish: PrintLocalTrajectory()
if saveCsvWhenFinish:          SaveTrajectoryToCSV()  // → Application.persistentDataPath

RoutinePlacementController.cs — Drag & Release XR
+

Gestiona el ciclo agarrar → soltar → confirmar del DragTarget. Al soltar, copia la pose al ExecutionTarget y orienta el Canvas de confirmación hacia la cámara principal.

1

Clonar y abrir en Unity

Abrir el proyecto en Unity 2022.3 LTS. Unity resolverá automáticamente los paquetes del manifest.json incluyendo todos los sub-paquetes de Meta XR SDK 83.

git clone <repo-url>

2

Configurar IPs en los scripts

Editar las IPs según la red del laboratorio. Cada script tiene el campo en el Inspector o en el código:

Asignar referencias en el Inspector

Para el headset: File → Build Settings → Android → Switch Platform. Activar Meta XR en XR Plugin Management. Para pruebas de escritorio usar Play Mode con el emulador de Meta o el Editor directamente.

Ajustes recomendados de seguridad

Workspace

Calibrar el WorkspaceFrame

Colocar el WorkspaceFrame exactamente en la base del robot y ajustar minRadiusXZ / maxRadiusXZ al alcance real del UR3 (radio máximo ~500 mm).

Velocidad

Reducir velocidades en primera prueba

Bajar speed1…speed6 al 50% del default y samplesPerSegment a 20+ para un movimiento más lento y seguro durante las pruebas iniciales.

Colliders

Configurar UR3SelfCollisionChecker

Agregar un CapsuleCollider a cada link del modelo y asignarlo en el array links del checker. Usar el mismo Layer para todos y habilitar colisiones en la Physics Matrix.

Debug

Activar gizmos en editor

Con drawWorkspaceGizmo = true en UR3WorkspaceLimiter, al seleccionar el objeto verás la caja verde y los círculos radiales que delimitan el workspace en la vista Scene.
