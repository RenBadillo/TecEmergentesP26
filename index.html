Digital Twin

UR3 Digital Twin en Unity XR

Gemelo digital interactivo del robot Universal Robots UR3 desarrollado en Unity, con cinemática inversa, trayectorias, comunicación HTTP con Flask y soporte para realidad extendida (XR/AR/VR).

Descripción General

¿Qué permite este proyecto?

Este sistema implementa un puente bidireccional entre un entorno virtual y hardware industrial real. Permite:

  • Visualizar y controlar el robot virtualmente mediante cinemática inversa (IK).
  • Definir una pose objetivo arrastrando un marcador en el espacio 3D.
  • Generar trayectorias interpoladas entre la posición actual y la posición objetivo.

Características Avanzadas

  • Enviar la trayectoria generada paso a paso a un servidor Flask que controla el hardware real.
  • Reproducir rutinas en un "robot fantasma" para validación visual previa.
  • Leer la telemetría (ángulos de los joints) del robot físico vía HTTP en tiempo real.

Arquitectura de 4 Capas

El sistema garantiza una transmisión segura y controlada de la intención del usuario hacia el robot real mediante las siguientes fases:

Capa 1 — Interacción

Gestión de hardware de Realidad Mixta (cámara passthrough, hand tracking, posición espacial). Contiene menús flotantes, dibujo de trayectorias 3D y emisión de comandos al servidor.

Capa 2 — Procesamiento

Resolución de Cinemática Inversa y cálculo de interpolaciones (MoveJ, MoveL, MoveC). Aquí operan las restricciones cinemáticas, autocolisión y validación del workspace.

Capa 3 — Simulación (Unity)

El gemelo digital renderizado. Recibe los conjuntos de ángulos válidos, anima la rutina visual y se encarga de la comunicación TCP/IP hacia el exterior.

Capa 4 — Robot Real

Ejecución de los comandos URScript en el brazo industrial. Proporciona retroalimentación de su pose actual y streaming de video desde la cámara montada en el efector final.

Pipeline de Seguridad

Antes de enviar cualquier movimiento al robot físico, el sistema ejecuta verificaciones obligatorias sobre el robot fantasma (ghost) sin afectar al equipo real:

  1. PreviewSolveToPosition(): Verifica si el solucionador IK logró converger dentro de la tolerancia requerida para alcanzar el target.
  2. CheckJointMargins(): (Vía UR3KinematicSafetyChecker) Revisa que ningún eslabón esté forzándose peligrosamente cerca de su límite mecánico.
  3. CheckSingularityHeuristic(): Detecta configuraciones cercanas a singularidades de codo (q3) o muñeca (q5), previniendo movimientos matemáticamente inestables.
  4. CheckContinuity(): Asegura que el salto angular entre dos frames consecutivos no sea brusco, evaluando el parámetro maxJointJumpDeg.
  5. HasSelfCollision(): (Vía UR3SelfCollisionChecker) Usa físicas de Unity para detectar penetraciones entre eslabones no adyacentes del robot.

Scripts de Validación

🛡️ UR3MotionValidator

Este script es el director orquestador. Para cada muestra interpolada de la trayectoria, ejecuta todo el pipeline de validación listado arriba. Si cualquier *check* falla, la trayectoria se rechaza inmediatamente y se muestra una razón.

🚧 UR3WorkspaceLimiter

Restringe proactivamente la posición del DragTarget al workspace operativo del robot en tiempo real. Utiliza un marco de referencia (AABB y límites radiales XZ) anclado a la base del robot para asegurar que el usuario no pueda apuntar fuera de alcance.

Núcleo de Cinemática Inversa (IK)

El cerebro detrás del movimiento del gemelo digital se divide en dos enfoques principales:

⚙️ UR3SimpleIKPhysical

Componente central absoluto del proyecto. Implementa un solucionador IK iterativo (CCD proyectado sobre ejes locales) complementado con dinámica física simulada. Maneja parámetros como velocidades por joint, aceleraciones, límites articulares y se sincroniza con el motor de físicas de Unity mediante Physics.SyncTransforms.

Uso dual:

  • Robot Live: Se ejecuta en LateUpdate para mostrar los movimientos fluidos en tiempo real en la escena.
  • Robot Ghost: Resuelve el posicionamiento offline a través de PreviewSolveToPosition(Vector3 pos, int iterations, float tolerance), clave fundamental para que el pipeline de seguridad analice el futuro sin comprometer el presente.

🔩 SimpleIKAxisControlled

Solucionador IK alternativo y más ligero, desprovisto de física y límites articulares pesados. Útil principalmente para objetos visuales de prueba, simulaciones ligeras o debug ejecutado puramente en LateUpdate.

Interacción en Realidad Extendida (XR)

El gemelo digital requiere interfaces de usuario adaptadas a entornos inmersivos.

✍️ DrawTrajectoryMeta

Permite al usuario dibujar trayectorias espaciales en el aire usando el gesto de "pinch" del hand tracking nativo de Meta Quest (OVR). El trazo inicia garantizadamente desde el efector final (Link6), y los vectores dibujados pueden exportarse como un archivo CSV para análisis posterior.

🎯 RoutinePlacementController

Controla la interacción física. Al agarrar y arrastrar una esfera (DragTarget) y soltarla, su pose geométrica se clona hacia un ExecutionTarget, detonando la aparición de un botón holográfico para confirmar y validar el movimiento.

📈 TrajectoryManager

Responsable de la previsualización visual del movimiento planificado. Mantiene un array de waypoints y los dibuja en escena usando un LineRenderer y pequeños prefabs esféricos en cada nodo de la ruta.

Herramientas de Interfaz de Usuario

  • KeyboardButtonController: Habilita el teclado nativo de MR (MRTK NonNativeKeyboard) para ingresar texto en cuadros de InputField desde el headset VR.
  • EnviarInputRobotProgram: Conecta los comandos ingresados en UI hacia un script ejecutor, reiniciando rutinas en el robot virtual.
  • UR3GhostPlayback: Toma secuencias pregrabadas (listas de ángulos) y las anima en el robot fantasma para evaluación visual.
  • ActivarObjeto: Script utilitario para alternar la visibilidad de modelos 3D en base a triggers de realidad mixta.

Comunicación y Servidores

El gemelo digital interactúa con el mundo exterior consultando e inyectando datos hacia dos servidores Python (Flask).

Servidor de Control (Movimiento)

UR3FlaskSender: Genera la trayectoria interpolada usando Lerp lineal y envía cada paso de la rutina hacia el endpoint POST /movimiento. Los valores de los 6 joints se empaquetan en un JSON en radianes.

UR3Client: Realiza *polling* (consultas continuas) cada 100 ms al endpoint GET /joints para recibir la telemetría actual del hardware y renderizarla en TextMeshPro.

Servidor de Visión (Hardware)

CameraGetButton / CameraVideoButton: Solicitan iterativamente frames de imagen al endpoint GET /snapshot.jpg simulando streaming de video en tiempo real (proyectado como textura 3D).

BotonDeteccion: Consume los endpoints /activar_deteccion y /desactivar_deteccion para prender o apagar pipelines de Computer Vision en el entorno Flask desde botones en Unity.
