Gemelo Digital Interactivo

UR3 Digital Twin — Unity XR

Bienvenido a la documentación oficial del proyecto. Este sistema implementa un gemelo digital (digital twin) altamente interactivo del brazo robótico Universal Robots UR3, desarrollado íntegramente en Unity.

El proyecto destaca por su integración de tecnologías avanzadas, permitiendo:

  • Visualizar y controlar el robot de forma virtual utilizando algoritmos de cinemática inversa (IK) para un posicionamiento preciso.
  • Definir poses objetivo en el espacio 3D simplemente arrastrando un marcador en la escena, con compatibilidad nativa para entornos de Realidad Extendida (XR), Aumentada (AR) y Virtual (VR).
  • Generar trayectorias suaves e interpoladas entre la posición actual del robot y la posición objetivo deseada por el usuario.
  • Transmitir estas trayectorias paso a paso hacia un servidor Flask, el cual se encarga de controlar el hardware del robot físico en el mundo real.
  • Previsualizar secuencias de movimiento de forma segura utilizando un "robot fantasma" (ghost) antes de ejecutar cualquier acción real.
  • Monitorear la telemetría obteniendo en tiempo real los ángulos de los joints del robot físico a través de peticiones HTTP.

Arquitectura del Proyecto

Para garantizar escalabilidad y mantenimiento, el sistema está estructurado en 4 capas fundamentales que conectan la interfaz del usuario con el hardware industrial.

Capa 1 — Interacción (MR Interface)

Es la capa más cercana al usuario, gestionando entradas de hardware (cámara passthrough, seguimiento espacial y hand tracking). Incluye gestos como "pinch", menús 3D, dibujo de trayectorias y envío de comandos. Los scripts involucrados son: DrawTrajectoryMeta, RoutinePlacementController, ActivarObjeto, KeyboardButtonController, y EnviarInputRobotProgram.

Capa 2 — Procesamiento

Aquí ocurre la "magia" matemática. Se capturan las coordenadas, se calcula la cinemática inversa, se interpolan trayectorias (MoveJ, MoveL, MoveC) y, lo más importante, se aplican las restricciones de seguridad. Comprueba autocolisiones, colisiones con superficies y límites del workspace. Usa: UR3SimpleIKPhysical (PreviewSolve), UR3KinematicSafetyChecker, UR3SelfCollisionChecker, UR3WorkspaceLimiter y UR3MotionValidator.

Capa 3 — Simulación

Es el gemelo digital renderizado en Unity. Recibe los ángulos válidos de la Capa 2 y ejecuta la rutina visual. Se encarga de la visualización de la trayectoria y de la comunicación TCP/IP hacia el mundo exterior. Usa: UR3SimpleIKPhysical (LateUpdate), UR3GhostPlayback, TrajectoryManager, UR3FlaskSender y UR3JointDebugger.

Capa 4 — Robot Real

La capa de ejecución física. El robot UR3 real recibe comandos URScript, ejecuta el movimiento físico y envía su pose actual de vuelta a la Capa 3 como retroalimentación. Además, una cámara en el efector final puede enviar imágenes. Usa: UR3Client, UR3FlaskSender, BotonDeteccion, CameraGetButton y CameraVideoButton.

Núcleo IK y Simulación

Estos componentes son el cerebro del movimiento del robot dentro del motor de Unity.

UR3SimpleIKPhysical

Es el componente central del proyecto. Implementa un sofisticado solucionador IK iterativo basado en CCD (Cyclic Coordinate Descent) proyectado sobre ejes locales. A diferencia de solucionadores básicos, este incluye dinámica física simulada: maneja velocidades, aceleraciones por joint, límites articulares y se sincroniza con el motor de físicas de Unity mediante Physics.SyncTransforms.

Se utiliza en dos modalidades clave:

  • Robot Live: Ejecuta movimientos en tiempo real durante el LateUpdate.
  • Robot Ghost: Resuelve la cinemática de forma offline usando el método crucial PreviewSolveToPosition(Vector3 pos, int iterations, float tolerance) para validar el movimiento antes de enviarlo.

Gestiona variables como arriveDistance, iteraciones, ejes locales y límites en grados.

SimpleIKAxisControlled

Es un solucionador alternativo y más ligero. Prescinde de la física y de los límites articulares complejos, por lo que es ideal para objetos de prueba o visualizaciones simples ejecutadas en LateUpdate.

Pipeline y Scripts de Seguridad

Antes de que el brazo mecánico real se mueva, el gemelo digital orquesta una serie de validaciones estrictas para evitar accidentes o daños en el equipo. El flujo sigue este orden:

  1. Convergencia (PreviewSolveToPosition): Verifica si la IK es capaz de alcanzar el objetivo dentro de una tolerancia permitida.
  2. Márgenes (UR3KinematicSafetyChecker): Ejecuta CheckJointMargins() para garantizar que ninguna articulación esté forzándose cerca de sus límites mecánicos.
  3. Singularidades (UR3KinematicSafetyChecker): Ejecuta CheckSingularityHeuristic() para evitar que las articulaciones q3 (codo) o q5 (muñeca) se acerquen peligrosamente a 0°, lo que causaría movimientos erráticos.
  4. Continuidad (UR3KinematicSafetyChecker): Ejecuta CheckContinuity() para asegurar que el salto entre el paso anterior y el actual no exceda el parámetro maxJointJumpDeg (bruscuedad).
  5. Autocolisiones (UR3SelfCollisionChecker): Usa Physics.ComputePenetration para evaluar HasSelfCollision(), detectando penetraciones entre eslabones del robot que no sean adyacentes.

UR3MotionValidator

Este script actúa como el director de orquesta. Valida trayectorias completas interpolando segmentos entre waypoints, delegando la revisión a los checkers individuales y usando el robot fantasma para simular cada muestra sin riesgo.

UR3WorkspaceLimiter

Actúa proactivamente en tiempo real restringiendo la posición del DragTarget al workspace operativo. Utiliza un sistema de coordenadas anclado a la base del robot, combinando cajas (AABB) y límites radiales para proyectar el objetivo al punto válido más cercano.

Interacción y Control XR

La experiencia de usuario inmersiva se logra gracias a los siguientes scripts:

DrawTrajectoryMeta

Permite al usuario dibujar una trayectoria en el aire mediante el gesto de "pinch" usando hand tracking (OVR). El trazo comienza siempre desde el efector final (Link6) para asegurar continuidad. Permite exportar los puntos dibujados como archivo CSV.

RoutinePlacementController

Controla la interacción de agarrar y soltar. El usuario maneja una esfera (DragTarget) y, al soltarla, su pose se transfiere a un ExecutionTarget, desplegando un botón de confirmación en la UI.

TrajectoryManager

Se encarga del renderizado visual de la ruta. Mantiene una lista de waypoints y los dibuja en el espacio 3D utilizando un LineRenderer y prefabs de marcadores esféricos.

ActivarObjeto

Un controlador sencillo que sirve para alternar la visibilidad del modelo 3D del UR3 y los menús asociados ante eventos XR.

Comunicación y Servidores

El gemelo digital no está aislado; se comunica de forma bidireccional con dos servidores Flask (uno de control y otro de visión) para sincronizarse con el hardware real.

UR3FlaskSender

Genera la trayectoria interpolada usando Lerp lineal, resuelve la IK en el ghost robot y envía cada paso de la rutina hacia el endpoint /movimiento mediante solicitudes POST. Los valores de los joints se envían siempre en radianes.

UR3Client

Realiza *polling* (consultas) cada 100 milisegundos al endpoint /joints para obtener los ángulos físicos reales del robot y mostrarlos en pantalla (TextMeshPro), asegurando que el estado real y virtual coincidan.

Endpoints de Control

  • GET /joints — Lee telemetría.
  • POST /movimiento — Envía trayectorias.

Endpoints de Visión

  • GET /snapshot.jpg — Devuelve un frame de la cámara (Usado por CameraGetButton y CameraVideoButton para streaming a FPS configurables).
  • GET /activar_deteccion y /desactivar_deteccion — Manejados por BotonDeteccion para encender o apagar procesos de visión computacional remotos.

UI, Teclado y Utilidades de Debug

Para facilitar las pruebas y la entrada de datos en un entorno sin teclado físico, el proyecto cuenta con varios módulos:

  • EnviarInputRobotProgram: Conecta un TMP_InputField con un componente RobotProgram para enviar texto y reiniciar rutinas.
  • KeyboardButtonController: Implementa el teclado flotante de Mixed Reality Toolkit (MRTK NonNativeKeyboard) en la escena XR para escribir cómodamente desde las gafas.
  • UR3GhostPlayback: Permite reproducir una secuencia pregrabada de ángulos en el robot fantasma para visualizar cómo se vería el movimiento completo.
  • JointReaderDegrees: Lee los ángulos locales de los joints en grados normalizándolos a rangos entre -180° y 180°. Se puede invocar con la tecla 'J'.
  • UR3JointDebugger: Herramienta visual para imprimir la telemetría del gemelo en un TextMeshPro dentro del entorno XR.

Dependencias del Proyecto

El proyecto está desarrollado en Unity 2022.3 LTS con target Android (optimizado para Meta Quest). Depende fuertemente de la versión 83 del SDK de Meta.

Configuración Rápida y Flujo de Uso

Pasos de Configuración

  1. Clona el repositorio y ábrelo en Unity.
  2. Asigna todos los prefabs y transforms en el Inspector según la arquitectura detallada.
  3. Edita los scripts UR3Client.cs y UR3FlaskSender.cs para que coincidan con la IP de tu red local.
  4. Ejecuta el servidor Flask en la PC conectada al controlador del UR3 físico.
  5. Presiona Play en Unity o compila al headset.

Resumen del Flujo

El usuario realiza un gesto (como un pinch o mover un target) ➜ El gemelo digital calcula el objetivo en la Capa 2 limitándolo al workspace válido ➜ El Pipeline de Seguridad simula la trayectoria ➜ Si es válida, el UR3FlaskSender envía la interpolación paso a paso mediante POST ➜ El UR3 físico se mueve y las cámaras retroalimentan el entorno de Unity.
